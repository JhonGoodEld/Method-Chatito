## 3. Objectif

MC-008 définit les mécanismes pédagogiques utilisés par le Méthode Chatito pour travailler : la perception des sons, la production phonétique, la prononciation, les contrastes phonologiques, la relation entre sons et représentations graphiques, l'apprentissage d'un système d'écriture, la correction phonétique, la correction graphique, et la consolidation de ces connaissances.

Il répond à la question :

**Comment le Méthode Chatito transforme-t-il les informations phonologiques et graphiques d'une langue en mécanismes pédagogiques adaptés à l'apprenant ?**

MC-008 ne définit pas les caractéristiques particulières d'une langue. Il définit comment ces caractéristiques sont exploitées pédagogiquement.

## 4. Portée

MC-008 couvre : la représentation phonétique, l'utilisation de l'IPA comme représentation commune, la comparaison entre systèmes phonologiques, le Pont phonétique, la perception des contrastes, la production des sons, la relation son-écriture, l'apprentissage des systèmes graphiques, la correction, la progression, la consolidation, l'adaptation à la langue source de l'apprenant, et l'adaptation à la langue cible.

MC-008 ne contient pas :

- l'inventaire phonologique d'une langue particulière ;
- la liste des phonèmes français ;
- la liste des phonèmes coréens ;
- les règles phonologiques propres à une langue ;
- les règles orthographiques propres à une langue ;
- les correspondances graphème-phonème propres à une langue ;
- des tableaux contrastifs permanents entre deux langues ;
- une liste fixe de difficultés « français pour hispanophones » ;
- une liste fixe de difficultés « coréen pour hispanophones ».

Ces informations appartiennent aux architectures linguistiques correspondantes.

## 5. Principe fondamental

Le Méthode Chatito sépare trois niveaux :

```
LANGUE → DONNÉES LINGUISTIQUES → MÉTHODE
```

Une architecture linguistique décrit ce qui existe dans une langue. MC-008 décrit comment travailler pédagogiquement ce qui existe.

Exemple : *FR-120 → Phonologie → Phonème → /y/* est une donnée linguistique. En revanche, *identifier, comparer, percevoir, produire, corriger, réactiver, consolider* constituent des mécanismes pédagogiques.

Cette séparation est obligatoire afin que MC-008 puisse être appliqué à plusieurs langues.

## 6. Séparation entre langue et méthode

Une langue fournit à MC-008 les données nécessaires :

```
Architecture linguistique
│
├── inventaire phonologique
├── caractéristiques
├── distribution
├── contrastes
├── règles
├── système d'écriture
└── correspondances son-écriture
        │
        ▼
      MC-008 → mécanismes pédagogiques
```

MC-008 ne modifie pas l'architecture linguistique. Il l'exploite.

## 7. IPA comme interlingua de représentation

L'Alphabet phonétique international (API/IPA) est, en lui-même, un **système commun de représentation phonétique** — un standard linguistique préexistant, non spécifique au Méthode Chatito. **MC-008 l'utilise comme interlingua de représentation** lorsque les unités phonologiques des architectures linguistiques sont représentées phonétiquement.

Cette précision importe : l'IPA ne constitue pas, à lui seul, un mécanisme pédagogique complet. Comparer deux symboles IPA identiques ou proches ne suffit pas à conclure une correspondance pédagogique — cela ne fournit qu'une représentation comparable, que MC-008 doit ensuite interpréter (voir section 9). Confondre le système de représentation avec le mécanisme qui l'exploite serait une erreur d'architecture.

```
Langue A (phonème → représentation IPA) ─┐
                                          ├── comparaison (via MC-008)
Langue B (phonème → représentation IPA) ─┘
```

MC-008 n'a donc pas besoin de stocker une table permanente Langue A ↔ Langue B. La comparaison peut être réalisée dynamiquement à partir des données disponibles.

**Principe :** l'IPA fournit le langage commun de représentation ; MC-008 fournit le mécanisme de comparaison et d'apprentissage. L'IPA ne remplace toutefois pas l'architecture phonologique d'une langue — il constitue une représentation commune, tandis que les propriétés, distributions et règles propres à chaque langue restent dans son architecture.

## 8. Architecture des données phonologiques

Pour utiliser MC-008, une architecture linguistique devrait pouvoir fournir, lorsque cela est pertinent : les unités phonologiques, leur représentation IPA, leurs caractéristiques pertinentes, leurs contrastes, leur distribution, les règles phonologiques pertinentes, et les relations avec le système d'écriture.

La quantité et la nature de ces données peuvent varier selon la langue. MC-008 ne présuppose donc pas que toutes les langues possèdent le même nombre de phonèmes, les mêmes catégories, les mêmes oppositions, le même système syllabique, le même système d'écriture, ni une relation régulière entre graphèmes et phonèmes.

## 9. Le Pont phonétique

Le Pont phonétique est le mécanisme central de MC-008 permettant d'établir une représentation comparable entre les systèmes phonologiques de la langue source et de la langue cible, puis d'exploiter cette comparaison à des fins pédagogiques. Il utilise les représentations IPA et les propriétés phonologiques déclarées dans les architectures linguistiques concernées.

Il ne constitue pas une bibliothèque de correspondances fixes. Il se décompose en **trois opérations distinctes** :

**A. Représentation** — convertir les unités déclarées par chaque architecture en une représentation comparable (IPA + propriétés) :

```
L1 → IPA + propriétés
L2 → IPA + propriétés
```

**B. Comparaison** — déterminer la relation entre unités : correspondance, similarité, différence, contraste, absence, ou relation indéterminée.

**C. Interprétation pédagogique** — convertir cette comparaison en hypothèse d'intervention, non en diagnostic définitif :

```
Comparaison → Relation phonétique → Priorité potentielle → Activité pédagogique
→ Production de l'apprenant → MC-002
```

Cette troisième opération conserve la frontière déjà établie dans MC-002 : **la comparaison linguistique génère une hypothèse ; l'apprenant fournit l'évidence.**

Le mécanisme général peut être représenté ainsi :

```
Architecture L1                          Architecture L2
├── unités phonologiques                 ├── unités phonologiques
├── représentations IPA                  ├── représentations IPA
└── propriétés déclarées                 └── propriétés déclarées
            │                                       │
            └───────────────┬───────────────────────┘
                             ▼
                  ┌─────────────────────┐
                  │   Pont phonétique   │
                  │  A. Représentation  │
                  │  B. Comparaison     │
                  │  C. Interprétation  │
                  └─────────────────────┘
```

Le Pont phonétique doit pouvoir : identifier les unités pertinentes de L1 et L2 ; utiliser leur représentation IPA comme représentation commune ; comparer les propriétés pertinentes déclarées ; identifier les correspondances, similarités, différences, contrastes et absences pertinentes ; générer des priorités pédagogiques potentielles ; fournir ces informations aux mécanismes pédagogiques de MC-008 ; réutiliser les observations produites par l'apprenant afin de confirmer, modifier ou écarter les hypothèses initiales.

Le Pont phonétique ne constitue pas un diagnostic automatique de la difficulté. Une relation identifiée entre deux unités constitue une information linguistique et pédagogique potentielle ; la difficulté réelle doit être vérifiée par l'observation de l'apprenant.

Le mécanisme ne doit pas contenir de correspondances permanentes propres à une paire de langues. Les données linguistiques appartiennent aux architectures concernées ; le mécanisme de comparaison appartient à MC-008.

> **Note sur la notation « L1/L2 ».** Cette notation décrit le cas courant d'un apprentissage avec une langue source unique. Elle ne constitue pas une contrainte structurelle : le mécanisme général est conceptuellement `Source(s) linguistique(s) → MC-008 → Target linguistic system`, ce qui laisse ouverte la possibilité de plusieurs langues sources (apprenants bilingues), d'une absence de langue de référence, ou d'une comparaison entre deux langues déjà apprises. Cette généralisation n'a pas besoin d'être résolue dans cette version — il suffit que le document ne la ferme pas accidentellement.

## 10. Comparaison entre langue source et langue cible

Le Pont phonétique compare les informations disponibles dans les deux architectures. La comparaison peut rechercher notamment : unités présentes dans les deux langues, unités absentes de la langue source, unités similaires mais non identiques, contrastes inexistants dans la langue source, différences articulatoires pertinentes, différences perceptives pertinentes, relations différentes entre sons et écriture.

Cette comparaison ne doit pas produire automatiquement une conclusion pédagogique définitive — elle produit une information de travail. L'évaluation réelle de la difficulté appartient au cycle pédagogique et peut être confirmée ou infirmée par les productions de l'apprenant.

## 11. Génération du Pont phonétique

Le Pont phonétique suit conceptuellement le cycle :

```
Identifier L1 → Identifier L2 → Extraire les représentations IPA pertinentes
→ Comparer les unités → Identifier les contrastes potentiels → Classer les priorités
→ Générer une intervention pédagogique → Observer la production → Corriger → Réévaluer
```

Le Pont phonétique est donc adaptatif. Il ne doit pas considérer qu'une différence théorique entre deux langues constitue nécessairement une difficulté réelle pour chaque apprenant.

## 12. Types de relations phonétiques

- **12.1 Correspondance directe** — une unité cible possède une représentation et des caractéristiques facilement accessibles dans la langue source.
- **12.2 Similarité** — une unité cible est proche d'une unité connue, mais présente certaines différences.
- **12.3 Contraste** — deux unités peuvent être proches acoustiquement ou articulatoirement mais jouer des rôles distincts dans la langue cible.
- **12.4 Absence** — une unité pertinente de la langue cible n'est pas présente dans l'inventaire source identifié.
- **12.5 Relation inconnue** — les données disponibles ne permettent pas de déterminer une relation suffisamment fiable. Dans ce cas, MC-008 ne doit pas inventer une correspondance.

## 13. Perception

La perception constitue une composante fondamentale de l'apprentissage phonétique. MC-008 peut organiser des activités permettant à l'apprenant de : distinguer deux sons, identifier un son, reconnaître un contraste, associer une représentation à un son, différencier des réalisations proches, reconnaître un son dans un contexte.

La perception doit pouvoir être travaillée avant ou parallèlement à la production.

## 14. Production

```
Perception → Identification → Imitation → Production contrôlée
→ Production en contexte → Production autonome → Production spontanée
```

Cette progression constitue un modèle pédagogique et ne doit pas être considérée comme une séquence obligatoire identique pour toutes les langues.

## 15. Correspondance son-écriture

Lorsque la langue possède un système d'écriture, MC-008 peut exploiter les relations entre son, représentation phonologique et graphème/unité graphique. La relation peut être régulière, irrégulière, contextuelle, multiple, ambiguë, ou inexistante.

MC-008 ne présuppose donc pas une correspondance univoque (1 son = 1 graphème).

## 16. Systèmes d'écriture

MC-008 doit pouvoir fonctionner avec différents systèmes d'écriture. Il ne doit pas être limité à l'alphabet latin, à une écriture alphabétique, ni à une relation phonème-graphème particulière. L'architecture linguistique décrit le système concerné ; MC-008 fournit les mécanismes pédagogiques nécessaires à son acquisition.

> **Frontière explicite :** MC-008 enseigne **comment** travailler pédagogiquement un système d'écriture donné (reconnaissance, production, consolidation). L'architecture linguistique déclare **comment fonctionne** ce système. Concrètement, MC-008 ne doit jamais contenir les règles du Hangul, les règles orthographiques françaises, des correspondances spécifiques, ni des règles de romanisation — ces éléments appartiennent respectivement à KO-*, FR-200, et à l'architecture de chaque langue concernée. Sans cette frontière tenue de façon stricte, MC-008 finirait par absorber, document après document, exactement le type de connaissance déclarative qu'il a été conçu pour exclure.

```
Architecture de la langue → Système d'écriture → MC-008
→ [Reconnaissance + Production] → Consolidation
```

## 17. Relation entre phonologie et orthographe

La prononciation et l'écriture sont liées mais ne doivent pas être considérées comme une seule connaissance. MC-008 distingue : *comprendre le son* ≠ *produire le son* ≠ *reconnaître l'écriture* ≠ *produire l'écriture*.

Un apprenant peut donc présenter des états différents pour chacune de ces dimensions. Exemple : Perception → Consolidée ; Production → En cours ; Lecture → Acquise ; Écriture → En cours.

MC-002 peut utiliser ces observations pour déterminer l'état de chaque connaissance concernée.

## 18. Correction de la prononciation

La correction phonétique doit être identifiable, explicative lorsque nécessaire, proportionnelle, contextualisée, et orientée vers la production future. Une correction ne doit pas seulement indiquer *« Incorrect »* — elle doit permettre d'identifier le mécanisme concerné.

Lorsque les données sont disponibles, la correction peut exploiter la représentation IPA, la différence pertinente, une description articulatoire, une comparaison perceptive, ou une représentation audio ou visuelle disponible.

## 19. Correction de l'écriture

La correction graphique suit le même principe général. Elle doit distinguer : erreur de connaissance du système, erreur de correspondance son-écriture, erreur de mémoire, erreur de production, erreur accidentelle.

Une erreur isolée ne doit pas automatiquement provoquer une régression de l'état d'acquisition. Cette règle est cohérente avec MC-002.

## 20. Progression pédagogique

```
Exposition → Reconnaissance → Discrimination → Compréhension
→ Production contrôlée → Production autonome → Production spontanée → Consolidation
```

La progression réelle doit dépendre de la langue, de la connaissance ciblée, du système d'écriture, du profil de l'apprenant, et des observations produites pendant l'apprentissage.

## 21. Interaction avec MC-001

```
MC-001 (leçon : connaissance, explication, pratique, production...) → MC-008 (phonétique / écriture)
```

MC-008 ne remplace donc pas MC-001.

## 22. Interaction avec MC-002

```
MC-008 (production phonétique) → évidence → MC-002 (diagnostic) → état du savoir
```

Inversement : `MC-002 (difficulté détectée) → MC-008 (intervention phonétique ciblée)`.

MC-008 ne décide donc pas seul de l'état de consolidation.

## 23. Interaction avec MC-004

**MC-004 = mécanisme général de transformation ; MC-008 = fournisseur des connaissances phonétiques/graphiques.** MC-008 peut fournir à MC-004 les connaissances phonétiques ou graphiques nécessaires lorsqu'une transformation pertinente existe — il n'exige pas que toute connaissance phonétique ou graphique passe systématiquement par une transformation.

MC-004 reste responsable du mécanisme général de transformation ; MC-008 ne fait que lui fournir la matière première spécifique à sa dimension.

La frontière reste : **MC-004 → comment transformer ; MC-008 → quelles dimensions phonétiques/graphiques sont mobilisées, lorsqu'une transformation pertinente existe.**

## 24. Interaction avec MC-005

MC-005 gère le vocabulaire. MC-008 peut utiliser des unités lexicales comme matériau pour la prononciation, la discrimination, la lecture, l'écriture, la production. Cependant, MC-008 ne devient pas responsable de l'acquisition lexicale.

```
MC-005 (vocabulaire) → MC-008 (travail phonétique / graphique)
```

## 25. Interaction avec MC-006

MC-006 assure la Consolidation Continue. Une connaissance phonétique ou graphique peut être réactivée selon l'intervalle temporel, les erreurs précédentes, les dépendances, la sélection aléatoire, ou l'état fourni par MC-002.

```
MC-002 (difficulté sur un contraste) → MC-006 (réactivation future) → MC-008 (travail perceptif/productif) → MC-002 (nouvelle observation)
```

## 26. Architecture multilingue

MC-008 est conçu pour fonctionner indépendamment d'une paire linguistique particulière. Le mécanisme ne doit pas nécessiter une version différente pour chaque combinaison — espagnol→français, espagnol→coréen, français→coréen, japonais→français, arabe→anglais, etc., peuvent utiliser le même mécanisme général lorsque les architectures concernées fournissent les données nécessaires.

## 27. Indépendance vis-à-vis de la langue

MC-008 ne doit pas contenir de catégories pédagogiques conçues exclusivement pour une langue particulière. Une caractéristique qui existe dans une langue mais pas dans une autre doit être fournie par l'architecture de la langue.

**La complexité linguistique appartient à l'architecture de la langue ; la stratégie pédagogique appartient à MC-008.**

## 28. Implémentation Hangulito

Hangulito constitue une première implémentation expérimentale pertinente des principes de MC-008. Son rôle n'est pas de définir MC-008 — il sert à vérifier qu'un mécanisme défini indépendamment du français peut être appliqué à une langue et à un système d'écriture structurellement différents.

```
MC-008 (Pont phonétique) → Hangulito → [Phonologie coréenne + Hangul/écriture]
```

Hangulito devient ainsi une implémentation de référence, et non une dépendance conceptuelle du modèle. Une implémentation future dans une autre langue devrait pouvoir réutiliser les mêmes principes sans modifier MC-008.

## 29. Limites du mécanisme

Le Pont phonétique ne doit pas être interprété comme un prédicteur parfait des difficultés. Une différence entre deux inventaires phonologiques peut constituer une difficulté réelle, une difficulté mineure, ou aucune difficulté observable. Inversement, une difficulté peut apparaître même lorsqu'une correspondance théorique existe.

**Comparaison linguistique ≠ diagnostic définitif.** La comparaison génère une hypothèse pédagogique ; la production réelle de l'apprenant permet de la confirmer ou de l'infirmer.

## 30. Principe de non-transposition

MC-008 interdit la transposition automatique de caractéristiques d'une langue à une autre. Le système ne doit pas supposer qu'une catégorie présente dans la langue source existe dans la langue cible, ni qu'une difficulté théorique devient nécessairement une difficulté pédagogique. Le système doit toujours partir des données déclarées dans les architectures concernées.

## 31. Architecture future LG-000

LG-000 devra définir comment une nouvelle langue peut être analysée et représentée afin de devenir compatible avec le Méthode Chatito. Dans le domaine phonologique, une architecture linguistique compatible avec MC-008 devrait notamment pouvoir déclarer, lorsque pertinent :

```
LG-000
│
└── Architecture linguistique
     ├── Identifiants
     ├── Relations
     ├── Phonologie
     │    ├── unités
     │    ├── représentation
     │    ├── propriétés
     │    └── contrastes
     ├── Écriture
     │    ├── unités
     │    └── relations
     └── Métadonnées
```

MC-008 peut alors exploiter ces informations sans connaître préalablement la langue.

## 36. Glossaire

| Terme | Définition |
|---|---|
| IPA / API | Alphabet phonétique international utilisé comme système commun de représentation des sons. |
| Interlingua phonétique | Usage que MC-008 fait de l'IPA — un système commun de représentation phonétique préexistant — comme langage intermédiaire permettant de comparer des unités provenant de langues différentes. |
| Inventaire phonologique | Ensemble des unités phonologiques pertinentes déclarées pour une langue. |
| Langue source (L1) | Langue de référence de l'apprenant utilisée pour établir le contraste pédagogique. Notation du cas courant ; le mécanisme général admet plusieurs sources ou l'absence de langue de référence (voir section 9). |
| Langue cible (L2) | Langue que l'apprenant cherche à acquérir. |
| Pont phonétique | Mécanisme de MC-008 qui compare les données phonologiques de L1 et L2 afin de générer une intervention pédagogique adaptée. |
| Correspondance | Relation identifiée entre deux unités représentées dans les systèmes comparés. |
| Contraste phonologique | Différence pertinente entre unités d'un système phonologique. |
| Perception | Capacité à identifier et différencier les unités sonores pertinentes. |
| Production | Capacité à réaliser une unité sonore de manière appropriée. |
| Graphème | Unité graphique utilisée par un système d'écriture. |
| Système d'écriture | Ensemble organisé de conventions permettant de représenter graphiquement une langue. |
| Correspondance son-écriture | Relation entre une unité sonore et une unité graphique. |
| Production phonétique | Réalisation orale d'une unité ou d'une séquence sonore. |
| Production graphique | Réalisation écrite d'une unité ou d'une séquence graphique. |
| Consolidation phonétique | Stabilisation de la perception et/ou de la production phonétique à travers différents contextes. |
| Donnée linguistique | Information décrivant le système propre à une langue. |
| Mécanisme pédagogique | Procédure utilisée par le Méthode Chatito pour enseigner, pratiquer, corriger ou consolider une connaissance. |
